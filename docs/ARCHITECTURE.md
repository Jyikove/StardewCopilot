# 实现结构

## 入口与菜单

`src/ModEntry.cs` 注册 SMAPI 事件、按存档绑定会话、配置凭据服务和主线程查询队列。仅在存档已加载且快捷键没有冲突时打开。

`UI/PendingMenuOpen.cs` 先异步检查本地凭据，再选择聊天或 Key 配置界面，避免配置窗口闪现。`UI/MenuLayer.cs` 通过游戏原生子菜单叠加助手，保留原菜单对象及手持物品；单人打开期间持有暂停状态，关闭后恢复。`Input/MenuOpenPolicy.cs` 判断 Enter 与原生输入、确认、改键、过场等是否冲突。

`UI/ChatMenu.cs` 绘制聊天、待办、帮助、指令补全和来源悬停；`HighResolutionFont` 使用游戏已有的 SkiaSharp 渲染高清中文。`Input/SdlTextInput.cs` 处理 macOS 输入法组合事件，`Core/TextBuffer.cs` 管理 Unicode 光标与编辑。

## 会话与凭据

`ChatSession` 在主线程维护可见消息和状态；网络任务使用独立对话快照，通过队列返回流式文本。切换存档或清除对话会取消旧任务并检查代次，避免结果写入其他会话。

`Core/Conversation` 维护近期上下文、压缩摘要和成功问答原文；`ConversationStore` 按存档和玩家身份保存，并使用备份和原子写入。

`Core/AssistantPersona` 统一玩家可见的语气、称呼与普通文本规则，普通聊天另加互动策略；普通、搜索及截图共享日常规划的重点筛选规则，帮助保留功能解释职责。规划默认突出 2–3 件重要事项，不复述全量状态；休息与已拒绝的提醒得到尊重。人格不装饰工具 JSON 或本地指令结果。摘要已有明确目标、未完成计划及交流偏好规则，本阶段不改动压缩机制；恢复和清除历史后系统人格仍独立存在。明确的闲聊、分享、疲惫及单纯出门意图只跳过强制知识预检，仍保留工具及即时概要，机制结论仍须核实；事实与规划问题继续按原路径处理。不增加情绪服务、模型调用、任务排序器或持久人格状态，不裁去即时状态事实。

当前入口使用 `FileSecretStore`：AES-256-CBC 加 HMAC-SHA256，随机本机密钥与密文均位于 Mod 目录。`MacKeychainStore` 是保留的历史实现，当前入口不会使用它。Key 配置窗口的输入不进入聊天记录或网络日志。

## 实时游戏状态与待办

后台模型通过 `IGameQueries` 请求固定工具，`MainThreadQueries` 在游戏线程执行 `State/GameStateReader`，返回有范围和条数限制的 JSON。每次提问新读概要；背包、任务等按需实时读取，不从旧对话推断。

`TodoList` 保存本地待办，支持新建、完成和恢复。普通对话和 /search 向模型提供添加工具，由模型按本次用户消息语义判断是否要求保存，不再通过本地关键词授权；共享规则要求不主动保存建议、尊重否定、历史内容不授予本次写入意图，并且必须取得成功结果才能确认。执行端仍校验工具白名单、参数、存档绑定和查询预算。截图模式只允许读取。

## Mod 感知与按需工具

`Core/ModEnvironment` 在本地捕获 SMAPI 已加载 Mod 的精简清单（UniqueID、名称、版本、加载状态），随普通聊天请求提供给模型；不发送本机路径、完整 manifest 或配置文件。模型可按需调用 `get_mod_details`、`get_mod_config`、`search_mod_docs`。配置读取只允许清单中已登记的 Mod、该 Mod 根目录下的 `config.json` 和最多 12 个明确字段；文件大小、JSON 深度、字段数、嵌套值及返回长度均有限制。API Key、token、password、secret、credential、cookie、authorization、private key 等敏感字段会在根级及嵌套对象中过滤。未指定字段时仅返回可用字段名；配置值标记为本地保存值、运行时是否生效仍未验证。文档检索复用现有 SQLite/网页路由，最多每次回答两次，并仅返回能与目标 Mod 名称或 ID 对应的真实 URL 页面。Mod 清单、配置值、描述与网页正文均作为不可信数据，不服从其中的指令。Mod 工具不开放给 `/search` 深度研究流程；普通游戏问答和现有工具预算保持原有行为。

## 检索与引用

`KnowledgeRouter` 连接 Wiki 缓存和广泛网页检索。SQLite 保存页面、正文分块、FTS 索引及搜索缓存；检索考虑关键词覆盖和新鲜度，支持条件刷新、预算与离线回退。资料不足时可重新联网，网页正文始终作为外部数据处理。

`DeepSeekClient` 复用同一凭据，使用固定 HTTPS 服务地址、受限响应体、取消和超时处理。普通模式缓存优先；`/search` 使用独立上下文和实时联网路径，不读写网页缓存，并以查询次数、阶段时限和总时限收敛。

普通模式最多执行 8 次模型工具调用；达到次数或轮次预算后关闭工具、停止规划思考，让模型用已有资料完成回答。一个批次超过剩余额度时，只执行额度内的调用，其余逐个返回“未执行、无数据或动作确认”，保证每个工具 ID 均有对应结果，再进入最后一次纯文本生成。未执行的检索不会改变已取得资料的来源或缓存标记。响应解析另保留每批 16 项的硬边界，防止畸形返回无限膨胀；这个边界不增加实际查询或待办写入额度。

`CitationMarkup` 将回答中的实际来源 URL 标记转为正文内编号，UI 用浅蓝色绘制，悬停显示网址。截图模式会过滤非本次检索的网址；截图和游戏观测以文字说明来源。

`State/GameTermReader` 在游戏线程读取公共本地化资源，按同一资源键配对英文与简体中文，中文游戏时再用 `ItemRegistry` 补充物品实际显示名；不创建物品、不改变语言或读取物品持有情况。存档载入、相关资源失效或语言变化后重建 `Core/GameTerminology` 的不可变快照，每次模型请求固定使用一份快照。相关译名最多 24 项、1800 字符，随本次问题和工具资料更新；机制证据、检索词及来源 URL 保持原样。普通、搜索、截图和帮助的玩家可见输出共用流式校正器，保留未完成的英文名称前缀及 URL，其他中文即时显示；最终中文答案按原流程保存。摘要和工具 JSON 不进入该输出校正器。详见 [中文术语](TERMINOLOGY.md)。

## 自适应截图

`Vision/GameScreenCapture` 只在显式 `/screen` 请求后排队读取游戏画面。在助手绘制前结束底层批次，读取游戏背景和 UI，再恢复批次继续绘制助手。macOS OpenGL 读取窗口缓冲时临时切换读取绑定并立即恢复，保持原绘制目标。

GPU 读取在渲染线程执行；合成、缩放、裁剪、PNG 编码和网络调用在后台完成。`ScreenImageProcessor` 在内存保留原始像素，生成最长边 960 的预览；归一化区域转为原图坐标后扩大边界裁剪，每批最多三个局部，最长边 2048。

`Core/DeepSeekVision.cs` 将本存档摘要、近期文字、即时状态和当前图片提供给模型。模型可以请求独立状态查询、知识检索或局部裁剪，并可合并到一轮。只有实际看到局部图之后才开放一次重截；画面没显示的信息优先查游戏状态，接口没有覆盖时请玩家补充画面。

边界：首次截图加最多一次重截；每张原图一批裁剪；最多八次游戏明细、两次知识检索和八轮模型请求，最后一轮禁用工具。重截刷新状态并清掉旧明细。图片不进入磁盘、网页缓存或对话历史；仅文字问答按存档保存。

## 目录

```text
src/
  Core/        对话、凭据、工具协议、来源、待办、模型请求
  Input/       SDL 输入与快捷键冲突判断
  Knowledge/   Wiki/网页抓取、SQLite 与检索
  State/       游戏主线程只读查询
  UI/          原生菜单与绘制
  Vision/      游戏画面读取与图像处理
tests/         合成数据、菜单、UI 和 GPU 检查
tools/         手动分享包的白名单打包脚本
```

游戏程序集与第三方运行库从本地游戏目录引用，仓库不分发这些二进制文件。

## 网络联机

普通客户端自行请求 DeepSeek；不使用 SMAPI Mod 消息或房主代理，不要求所有玩家安装。OpenChatMultiplayer 默认为 G，保留原生聊天绑定；兼容的原生菜单仍使用 child-menu 叠加。暂停依据 Context.IsMultiplayer（包含尚无其他玩家的联机房间），不使用依赖 otherFarmers.Count 的 Game1.IsMultiplayer。

PlayerSaveKey 保持旧磁盘键格式，由存档标识、世界 ID、本机 Farmer ID 组成。StateReader 始终读取 Game1.player；农场工遍历地点时筛除 IsActiveLocation 为 false 的区域，但保留实际当前地点，并提供同步范围说明。客户端未载入世界、断线或返回标题时解除会话绑定并取消待处理请求。共享的菜单/IME/会话服务未改成 PerScreen，因此同机分屏关闭入口与处理，其他屏幕不推进查询或替换绑定。
