# 游戏内中文术语

0.20.0 使用游戏实际资源校正专有名词，避免让模型从英文 Wiki 自行创造译名。不更换检索服务，不额外调用翻译 API，不缓存个人数据或分发游戏资源文件。

## 数据与边界

`GameTermSources` 通过相同资源键配对英文与简体中文的物品、武器、工具、建筑、NPC、附魔、增益及属性名称。`GameTermReader` 使用指定语言的内容读取接口，不切换全局语言；中文游戏时还从 `ItemRegistry` 的内部名及实际显示名补充物品，包括当前已加载的内容修改。资源失效、重新进入存档或语言改变后刷新。

以本机 1.6.15 游戏资源验证的示例：

| 英文 | 游戏中文 |
| --- | --- |
| Templar's Blade | 圣堂之刃 |
| Steel Falchion | 钢刀 |
| Lava Katana | 熔岩武士刀 |
| Galaxy Sword | 银河剑 |
| Infinity Blade | 无限之刃 |
| Crusader | 十字军 |
| Crit. Chance | 暴击率 |
| Crit. Power | 暴击力量 |

译名不是机制证据，也不说明玩家持有某物品。伤害、获取条件、附魔实际效果等继续依照 Wiki 与即时查询核实；不会因为术语表中出现某种物品，就声称背包里有它。

每次请求只发送与问题、当前查询或检索资料匹配的有限对照，不发送整本物品目录。英文正文、搜索词、来源 URL、工具名和参数保持原样。模型先按对照组织中文回答，输出层再将已知英文名称精确替换为游戏中文名；跨流式分段的名称也可处理。URL、英文单词内的子串和机器工具结果不替换，其他中文不必等完整回答生成后才显示。

同一英文对应多个不同中文时不擅自选择；没有可靠译名的模组内容、未知名称或不同英文表述不保证自动匹配，提示模型保留原名并给简短中文解释，说明官方译名尚未确认。非中文游戏仍可使用基础中文字符串资源，但部分只在物品实例中生成的自定义名称无法补全。不能把“未覆盖”包装成已确认翻译。

新回答在显示和保存前完成校正；重新载入历史时仅校正旧助手消息的显示，玩家原文和已有历史文件不批量改写。词表仅保存在内存，不写入网页缓存、存档或分享包；摘要仍沿用原有压缩机制。

0.20.1 合并翻译后重复的名称，例如“Steel Falchion（钢刀）”只显示“钢刀”，不会留下“钢刀（钢刀）”。流式分段和重新载入的旧消息同样适用；有意义的属性说明、不同名称及来源网址保留。模型也被明确要求直接使用游戏中文名，不在后面附原名或别称。

## 验证

自动测试分为合成协议测试和直接读取安装游戏资源的测试，运行方式见根目录 TESTING.md。前者检查分段、链接保护、同词歧义、上下文上限、各入口和保存结果；后者验证上述译名及游戏属性标签，不调用 DeepSeek 或读取玩家存档。

安装后重启，确认 SMAPI 加载 0.20.0。分别在普通对话、`/search` 与 `/screen` 中询问武器、附魔和食物增益。可复问“圣堂之刃好用吗，有什么更好的选择？”：重点检查回答中的武器名与游戏物品提示一致，Crusader 使用“十字军”，效果解释以中文为主，且引用编号仍能悬停显示原网址。注意译名校正不代表伤害或获取条件已验证，仍需核对实际来源。

测试流式回答是否有明显英文半词残留，退出重进后新记录是否保持中文；内容模组修改显示名后，重新加载资源或存档复查。未知模组物品应坦诚说明译名未确认，不能用自行翻译的名称冒充游戏内名称。真实模型的最终措辞与自定义内容兼容性仍需游戏内观察。
